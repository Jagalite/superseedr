# Torrent download diagnostics validation

## Scope

These are local synthetic results from 2026-09-22 on one machine. The first
comparison used one debug build; a final-source smoke appears below after the
last detector and failure-handling edits. The generated payload and peer
fixtures are fictional. Raw summaries,
samples, and diagnostic JSONL files are under
`tmp/download-diagnostics-validation/` in this workspace. The payload files
remain in the external synthetic run directory and can be regenerated by the
command below.

The initial engineering gate for default Debug is no more than 5% download
throughput regression, 10 MiB extra peak process memory, 50 ms maximum sample
delay, and no dropped diagnostic records in this routine fixture. These are
provisional thresholds. A target-limited synthetic run cannot qualify live
swarm performance or establish CPU overhead precisely.

## Matched download runs

The runs used one generated 64 MiB torrent, four local TCP peers, a 20 Mbps
target, three seconds of warmup, and 12 seconds of measurement. Each detail was
run twice. The longer run used a 128 MiB torrent, five seconds of warmup, and
30 seconds of measurement. All three modes used the same build, piece size
(256 KiB), storage volume, and traffic target.

```bash
target/debug/superseedr --json synthetic-load \
  --diagnostics <off|debug|trace> --mode download --transport tcp \
  --torrents 1 --peers 4 --size-per-torrent 64MiB \
  --piece-size 256KiB --target-gbps 0.02 \
  --duration-secs 12 --warmup-secs 3 --metrics-interval-ms 1000 \
  --out /Volumes/seed2/Projects/superseedr/diag-perf
```

All nine download runs completed without session issues. The matched short-run
Debug mean was 0.13% below Off; the longer Debug run was 0.02% above its Off
counterpart. These differences are inside run variability and the configured
rate limit. The longer Debug log had two periodic summaries, one final summary,
zero dropped records, and 68 suppressed repeated details. Trace reported
bounded loss: 162 dropped and 20,835 suppressed observations in the longer run.
Trace is an explicit mode; its file family still has a 6 MiB retention limit.

The final-source build was rerun with the 12-second fixture and output under
`./tmp`. Off, Debug, and Trace completed at 20.022, 20.022, and 20.045 Mbps,
respectively, with no session issues. Debug retained 6,282 bytes and Trace
760,290 bytes. Those summaries and logs are under
`tmp/download-diagnostics-final/`.

Two final-source runs using the external output volume reported an incomplete
diagnostic flush at the two-second shutdown deadline (one Debug, one Trace).
A repeated Debug run on that volume completed. The failed Debug log had a final
summary and 12 `piece_write_failed` records, but the evidence does not isolate
the source of the writer delay. The failures and their samples are preserved in
`tmp/download-diagnostics-validation/external-final/`. This is a real limit of
best-effort logging on that storage path, and it remains visible rather than
being counted as a successful performance run.

## Seeding and connection churn

An upload-only Debug run used eight torrents and 16 peers for 15 seconds. Seven
torrents created no diagnostic file. One produced a two-record validation to
seeding transition; no torrent emitted periodic seeding records. The run had no
session issues.

A 15-second Trace run used four downloading torrents, 16 peers, one-second
session lifetimes, and 250 ms reconnect delays. It completed 192 connections
and 192 disconnects without session issues. The four retained torrent logs were
618–660 KiB each. Per-torrent dropped counts were 18–46, suppression counts
were 29,767–30,044, and writer failure and quota eviction counts were zero.
This confirms bounded output and broadly even sharing under this churn pattern;
it does not cover every queue or filesystem failure mode.

## Content and remaining qualification

The local audit parsed 12,797 records across 16 JSONL files, including the
final-source and incomplete-flush artifacts. Every record had
the required schema and identity fields; the largest encoded line was 1,178
bytes. All segments stayed below 2 MiB. The audit found no magnet link,
announce query, payload byte, or download path field. Its machine-readable
result is `tmp/download-diagnostics-validation/audit.json`.

The tests cover Off, lifecycle epochs, temporary Trace expiry, queue saturation
fallback, rotation, quota pruning, exclusive log-root ownership, unavailable
storage retry, a Unix permission failure, and a blocked writer returning at the
two-second shutdown deadline. Native Clippy, formatting, Wasm compilation, and
the healthy stall reproduction also pass. A live swarm comparison and longer
observation for bytes per torrent-hour remain open. Peak CPU varied
substantially between repeats, so the current measurements do not establish a
precise CPU regression.
